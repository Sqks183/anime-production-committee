# 游戏规则设计原则

## 确定性

同一初始状态、相同决策和相同种子应产生相同结果。C++ 不获取系统时间、系统随机源、浏览器状态或网络数据。随机种子由 TypeScript 持有，通过请求显式传入；存档记录种子。

当前示例接收并验证 seed，但不使用随机数，也不推进种子。固定初始种子为 12345。未来引入随机事件前，需要明确算法、调用顺序和种子推进协议，不能悄悄更换算法破坏重放。

## 责任边界

规则属于 C++ 核心，不属于 React 或 Zustand。React 只发出操作，Zustand 协调异步调用并采用结果。C++ 接口保持明确输入输出，不保存全局游戏会话、不读写存档、不管理种子生命周期。

## 当前唯一示例规则

这是构建与接口验证夹具，不是正式数值或平衡方案：

- budget 为非负 JavaScript 安全整数；progress 为 0–100 整数；seed 为 uint32。
- progress 小于 100 时，一次操作扣除 5000，progress 增加 5 并截断至 100。
- 资金不足时返回 INSUFFICIENT_BUDGET，不扣款、不更新进度。
- progress 已为 100 时不再扣款。
- 返回更新后的 budget、progress 和中文 message；不修改输入对象。
- 非法 JSON、类型或范围错误返回 INVALID_INPUT。

前端显示这些示例说明，但不自行计算返回预算和进度。

## 尚待团队设计

企划资源、员工工作效率、质量计算、事件概率、工期惩罚和商业评价均未确定。预留接口不代表这些系统已经开发。未来规则变更需同时更新协议、C++ 单元测试、WASM 集成测试和规则文档。
