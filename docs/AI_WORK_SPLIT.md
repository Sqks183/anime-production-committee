# 个人 AI 协作分工

- 更新日期：2026-11-22
- 适用项目：动画制作委员会 V1.0
- 本文只划分 zm 与三个协作角色的工作方式，不替代真人团队模块负责人分工。

## 总体原则

你（zm）是项目负责人，负责最终规则决策、共享核心文件所有权、跨模块集成和验收。ChatGPT、大参数模型和 Flash 是不同工作角色，不是三个独立的项目负责人。

真人团队原有模块责任保持不变：

- @Sqks183：企划系统、员工系统（含外包）的设计、实现与交付。
- @pyxz0：素材系统、制作事件系统的设计、实现与交付。
- zm：公司经营层、核心制作与经营规则、跨模块集成与长期反馈。

AI 可以辅助模块负责人完成分析、代码和界面工作，但不能因此改变模块所有权，也不能绕过负责人确认。

## A. 我和 ChatGPT 一起做

**定位：总案搭档、规则分析、系统架构与集成审查。**

### 主要工作

1. **总体规划**
   - 维护阶段目标、开发顺序、依赖关系和风险清单。
   - 把大目标拆成可独立验收的任务，明确输入、输出、修改范围和验收标准。
   - 判断新提议属于规则决策、契约调整、模块实现还是体验优化，避免把执行细节重新拉回总案讨论。

2. **zm 负责的核心规则**
   - 公司经营层：周推进中的公司级结算、资金与声望唯一写入、公司终局、经营总结。
   - 核心制作规则：五阶段结果、质量评价、商业表现、作品结算、渠道分账的跨系统约束。
   - 长期反馈：作品履历唯一写入、前作关联、续作规则、竞争结算和结局评价。
   - 处理企划、员工、事件模块之间的规则冲突，保证各模块调用同一套规则。

3. **跨模块集成与审查**
   - 审查模块提案、PR diff、状态字段、接口和资金对账。
   - 检查随机数消费顺序、存档兼容、状态机和重复结算风险。
   - 设计原生/WASM/浏览器验收场景，检查固定种子重放和经营闭环。
   - 把已确认的规则同步到正确文档，维护实现状态，不让文档领先代码。

4. **任务指令与协作**
   - 为大参数模型和 Flash 编写具体执行指令。
   - 审查模型产出，指出偏离范围、漏测和跨模块副作用。
   - 将需要 zm 决策的问题单独列出，不替你擅自决定。

### 主要交付

- 规则决策记录、跨模块接口约定、集成任务、验收清单。
- 核心规则审查意见、代码/PR 审查、测试方案和结果核对。
- PROGRESS.md、GAME_RULES.md、DATA_MODEL.md、API.md 等文档的状态同步。

### 不做

- 不替 Sqks183 或 pyxz0 重新设计其完整模块。
- 不凭空增加系统或改变已经确认的玩法边界。
- 不把 TypeScript 类型存在、文档提案或 Mock 页面当作 C++ 功能已完成。

## B. 和大参数模型一起做

**定位：复杂工程实现与后端规则代码执行者。**

### 主要工作

1. C++ 核心规则实现和复杂状态转换。
2. game_rules.hpp 参数集中、规则计算、确定性随机逻辑。
3. WASM/Embind 接口实现与跨语言数据问题排查。
4. 原生测试、真实 WASM 测试和边界用例。
5. 复杂算法、资金结算、渠道分账、市场生成、员工/供应商行为、事件效果等需要多条件联动的实现任务。
6. 对性能、状态一致性、存档兼容和固定种子重放进行工程检查。

### 适合交给它的任务

- 规则已经明确、需要把规则转成 C++ 行为的任务。
- 多个状态字段联动、需要梳理执行顺序的任务。
- 需要补齐原生/WASM 测试、排查复杂 bug 的任务。
- 需要提供实现方案、代码 diff 或独立分支交付的任务。

### 交付要求

每项任务必须先给出：
- 修改文件清单与明确不修改的文件。
- 依赖的契约字段和规则来源。
- 状态变化、资金变化、随机数消耗点。
- 正常路径、拒绝路径和边界测试。
- 实际执行过的测试命令与原始结果；未执行的测试明确标注。

### 文件边界

game_core.cpp、game_rules.hpp、embind.cpp、核心测试、gameV3.ts、fixtures、browser.test.mjs 和存档格式仍由 zm 单点合入。

大参数模型可以负责这些文件的实现分析、补丁草案、隔离分支代码和测试建议，但不能与 zm 或其他模型同时直接修改同一共享文件；最终由 zm 审查并集成。模块自有文件则按真人模块负责人授权的任务范围执行。

## C. 和 Flash 模型一起做

**定位：前端界面、交互呈现与视觉资源执行者。**

### 主要工作

1. React 页面、展示组件、布局和交互体验。
2. Tailwind/CSS 样式、响应式适配和视觉一致性。
3. 员工、企划、供应商、事件、作品履历等模块的界面呈现。
4. 空状态、加载状态、错误提示、禁用状态、结果反馈等体验细节。
5. 静态素材接入、图片尺寸与展示适配。
6. 组件测试、视口检查和浏览器 UI 验收辅助。

### 适合交给它的任务

- 核心接口和字段已经明确，需要将数据变成页面。
- 已有页面需要拆分组件、改善布局或适配移动端。
- 需要把规则回执、阶段状态、员工能力和企划信息清晰展示。
- 需要素材接入、视觉规范统一和交互细节完善。

### 交付要求

- 页面只消费核心返回的数据，不在 React 中复制经营公式。
- 先说明使用的接口、字段和页面状态，不自行发明核心字段。
- 提供组件测试、关键视口检查和实际浏览器验证结果。
- 若接口缺字段或规则不清，先提问题，不用前端 Mock 掩盖核心缺口。

### 文件边界

Flash 主要处理 apps/web/src/pages/、components/、styles/ 及明确分配的静态资源和对应组件测试。

gameV3.ts、fixtures.ts、services/、stores/、存档格式和浏览器核心场景脚本属于共享边界；需要修改时先向 zm 提交字段/接口需求，不与 zm 并行改动。前端不得计算质量、成本、收入、声望或事件概率。

## 协作顺序

1. zm 与 ChatGPT 明确目标、规则依据、依赖和验收条件。
2. 按任务性质交给大参数模型（复杂后端）或 Flash（前端呈现）；模块任务仍由对应真人负责人统筹。
3. 模型先检查工作区和相关文件，只改授权范围，不覆盖他人未提交工作。
4. 涉及共享契约或核心文件时，先提交方案/补丁，由 zm 单点合入。
5. zm 与 ChatGPT 审查 diff、测试证据和跨模块影响。
6. 通过验收后更新 Issue、进度和相关规则文档。
