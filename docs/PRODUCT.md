# 动画制作委员会

## 产品定位

浏览器端、单人、轻量动画公司经营模拟游戏。玩家在有限资金、人员和工期下推进动画企划，权衡质量、进度与商业表现。题材强调动画制作流程，不依赖大量分支剧情或原创美术。

## 核心体验目标

- 从企划到成品，体验制作过程中的资源取舍。
- 经营决策应影响结果，而非单纯点击升级。
- 相同初始条件与决策可以重现结果，便于理解策略和复盘。
- 最终希望形成开始、经营、结算、再次体验的完整周期。

以上是产品方向，不代表本次已经实现。

## 当前版本 v0.1.0

本次只建立工程基础：

- 首页、临时经营验证页、加载与错误提示。
- TypeScript 调用真实 C++17 WebAssembly，以 JSON 交换数据。
- 固定输入资金 100000、进度 20、种子 12345；通过 C++ 示例推进接口检查状态更新。
- Zustand 管理会话状态；IndexedDB 手动保存、读取单一浏览器存档。
- 前端单元测试、C++ GoogleTest、真实 WASM 集成测试与静态构建流程。

该页面不是正式游戏 UI；示例计算不是正式玩法或数值平衡。

## 不在本次范围

没有实际企划系统、员工系统、质量系统、市场模拟、经营事件、作品评价、结算或重开循环。除 advance_day 外的核心接口只返回 NOT_IMPLEMENTED。

没有独立后端、远程数据库、账户、联网同步、多人功能、Electron 或 Phaser。本地存档仅属于当前浏览器的当前站点源，清理浏览器数据会丢失存档。

## 后续范围管理

一周开发、三人协作的目标应优先完成最小经营周期。由负责人确定规则与接口后，再分配前端交互、纯规则实现和验证任务；工程初始化不预先替代团队决定系统深度或平衡参数。
