# M4 商业结算手算 Fixture（集成对账用）

> 状态：集成验证样例，不是数值平衡基准
> 日期：2026-11-26
> 依据：DEC-COMM-001/002/003、DEC-BD-001、DEC-ECON-001、DOMAIN_ARCHITECTURE §10.6
> 用途：验证投资本金、制作费、实际制作成本、BD 收入与非 BD 委员会商业分配彼此独立。
>
> 本文金额均为人为构造的整数输入，只用于验证账务口径；不代表收入预测、费率、渠道权重或平衡参数。未在样例中出现的费用/倍率不代表规则不存在。

## 1. 固定输入

### 1.1 项目与投资

| 项目 | 输入 |
|---|---:|
| 制作费 / 合同预算 | 1,000 |
| 委员会总投资池 | 2,000 |
| 玩家投资比例（样例 A） | 30% |
| 玩家初始投资本金（样例 A） | 600 |
| 实际制作成本 | 1,100 |
| 制作毛利 | -100 |

由 DEC-COMM-003：

- 委员会总投资池 = 制作费 × 2 = 2,000。
- 制作费是制作公司的收入；实际制作成本是制作公司的费用。
- 玩家初始投资本金 = floor(2,000 × 30% / 100) = 600。
- 制作毛利 = 1,000 - 1,100 = -100。
- 投资本金不是制作收入，不能用制作毛利替代投资损益。

### 1.2 商业渠道输入

假设本项目为委员会项目，以下渠道均已按规则开放：

- 国内配信：由对应委员会成员开放。
- 海外发行：由对应委员会成员开放。
- 玩具/周边：由对应委员会成员开放。
- 音乐：由对应委员会成员开放。
- 电视版权：本样例关闭，收入为 0。
- BD/DVD：基础渠道，无需委员会成员。

假设未购买电视服务、没有电视台成员提供播出，因此本样例不应用电视曝光倍率。下表是已经完成渠道适用系数计算后的毛收入输入，不再从潜力/质量/热度等上游变量反推。

| 渠道 | 毛收入 | 归属/处理 |
|---|---:|---|
| 国内配信 | 230 | 进入委员会商业池 |
| 海外发行 | 160 | 进入委员会商业池 |
| 玩具/周边 | 92 | 进入委员会商业池 |
| 音乐 | 46 | 进入委员会商业池 |
| 电视版权 | 0 | 关闭，无收入 |
| BD/DVD | 92 | 始终归制作公司；公司取得 50% |
| **非 BD 毛收入合计** | **528** | 委员会项目商业池的计算起点 |
| **全部窗口毛收入** | **620** | 仅用于展示，不作为单一分账池 |

另设适用且已约定的前置商业成本为 28。它是本 fixture 的输入，不代表新增费用类别或默认收费。

## 2. 样例 A：委员会项目，玩家投资 30%

### 2.1 非 BD 委员会商业池

| 步骤 | 算式 | 结果 |
|---|---|---:|
| 非 BD 毛收入 | 230 + 160 + 92 + 46 + 0 | 528 |
| 扣除适用前置商业成本 | 528 - 28 | 500 |
| 玩家商业分配 | 500 × 30% | 150 |
| 其他委员会成员分配合计 | 500 × 70% | 350 |
| 分配总额核对 | 150 + 350 | 500 |

**关键结论：** 分配基数是扣除适用前置商业成本后的 500，不是毛收入 528。当前模型只记录玩家的投资比例和实际投资金额：玩家按 30% 取得 150，其他成员合计取得剩余 350，不记录其他成员细分比例或分配明细；不采用本金优先返还。

### 2.2 BD/DVD

| 项目 | 算式 | 结果 |
|---|---|---:|
| BD/DVD 毛收入 | 输入 | 92 |
| 制作公司所得 | 92 × 50% | 46 |
| 综合成本部分 | 92 × 50% | 46 |

BD/DVD 的 46 公司所得不进入委员会商业池，也不按 30% 投资比例分配。综合成本部分已经包含在 BD 的 50/50 规则中，不得再重复扣一次现金或制作成本。

### 2.3 三类口径分别核对

| 账务视角 | 算式 | 结果 |
|---|---|---:|
| 制作经营毛利 | 制作费 1,000 - 实际制作成本 1,100 | -100 |
| 投资损益 | 累计商业分配 150 - 初始投资本金 600 | -450 |
| BD 公司所得 | 92 × 50% | +46 |
| 项目净现金贡献（`finance_summary.profit`） | -100 + (-450) + 46 | -504 |

三类业务口径是不同事实：

- 制作经营毛利衡量制作公司是否以制作费覆盖实际制作成本。
- 投资损益衡量玩家作为投资方获得的商业分配相对投入本金的结果。
- BD 公司所得归制作公司，不进入委员会商业池，也不计入投资方商业分配。

三类口径不得互相替代；它们合计对应公司视角的项目净现金贡献 -504。现行接口仍使用 `finance_summary.profit`（名称“项目利润”），本 fixture 不重命名或扩展该字段。

### 2.4 样例 A 的最小 Finance / Archive 对账

假设公司期初现金为 5,000，仅列本项目相关流水。为便于手算，同类流水合并展示；实现可按实际周次拆分，总和不变。本 fixture 假设 1,100 实际制作成本全部归入 `production`；若实现拆分为 `salary`、`outsourcing` 等类别，应按正式分类拆流水，合计仍为 1,100。

| 时点 | Finance category | entry.amount | 说明 |
|---|---|---:|---|
| `start_work` | `investment_paid` | -600 | 玩家投资本金 |
| `start_work` | `contract_received` | +1,000 | 制作费并入公司现金 |
| 制作过程 | `production` | -1,100 | 实际制作成本汇总 |
| 交付结算 | `commercial_share_received` | +150 | 非 BD 净池的玩家分配 |
| 交付结算 | `commercial_share_received` | +46 | BD/DVD 公司所得 |
| **项目合计** | — | **-504** | 与 `finance_summary.profit` 一致 |
| **期末公司现金** | — | **4,496** | 5,000 - 504 |

本 fixture 将 28 的前置商业成本视为委员会池在分账前的扣减，不再作为公司第二笔 `distribution` 支出。若实现约定由公司代垫，必须明确相应流水并同步调整分池，不能既从池中扣除又重复扣公司现金。

Archive 至少应能还原：

- `contract_received = 1,000`、`investment_paid = 600`、`commercial_share = 196`、制作成本 `1,100`，并按现有公式得到 `profit = 1,000 + 196 - 600 - 1,100 = -504`。
- 全部渠道毛收入 `620`，满足 `Σ channel_breakdown.revenue = commercial_revenue`；公司所得 `196`，满足 `Σ company_received = commercial_share`。
- 非 BD 毛收入 `528`、前置成本 `28`、净池 `500`、玩家分配 `150`、其他成员合计 `350`，以及 BD 公司所得 `46` 可由交付快照中的输入复算。若现有 `channel_breakdown` 形状无法承载这些事实，必须先提交契约差异，不得由模块私加字段。

## 3. 样例 B：同一项目输入，玩家投资 100%

除玩家投资比例外，其他输入与样例 A 完全相同。

| 项目 | 算式 | 结果 |
|---|---|---:|
| 初始投资本金 | 2,000 × 100% | 2,000 |
| 非 BD 净商业池 | 与样例 A 相同 | 500 |
| 玩家商业分配 | 500 × 100% | 500 |
| 其他成员商业分配 | 500 × 0% | 0 |
| 投资损益 | 500 - 2,000 | -1,500 |
| 制作毛利 | 1,000 - 1,100 | -100 |
| BD 公司所得 | 92 × 50% | +46 |

此例用于确认：

- 100% 投资比例下，玩家取得全部委员会净商业池。
- 不存在先返还本金、再分利润的瀑布式分配。
- 投资损益仍与制作毛利、BD 公司所得分开。

## 4. 样例 C：承制项目

使用同样的制作费、实际制作成本与 BD 毛收入，但合作模式改为承制。

| 项目 | 结果 | 说明 |
|---|---:|---|
| 制作费收入 | +1,000 | 客户支付给制作公司 |
| 实际制作成本 | -1,100 | 制作公司承担 |
| 制作毛利 | -100 | 允许出现制作亏损 |
| 投资本金 | 0 | 承制模式不创建委员会投资池 |
| 委员会商业分配 | 0 | 不创建委员会，不参与非 BD 常规窗口分配 |
| BD/DVD 公司所得 | +46 | BD/DVD 始终归制作公司 |

承制项目不得因为拥有渠道或商业表现而被错误地分配非 BD 委员会商业收入。

## 5. 集成必须保持的恒等式

1. 委员会总投资池 = 制作费 × 2。
2. 玩家初始投资本金 = floor(委员会总投资池 × 玩家投资比例 / 100)。
3. 制作毛利 = 制作费收入 - 实际制作成本。
4. 非 BD 净商业池 = 非 BD 毛收入 - 适用且已约定的前置商业成本。
5. 玩家商业分配 + 其他成员合计分配 = 非 BD 净商业池；不记录其他成员细分分配。
6. 玩家投资损益 = 玩家累计商业分配 - 玩家初始投资本金。
7. BD 公司所得 = BD/DVD 毛收入 × 50%；其余 50% 为综合成本，不重复扣账。
8. 承制模式的委员会投资本金、委员会非 BD 商业分配均为 0。
9. 任何一笔实际现金变化只进入 Finance 一次；项目账仅做归因，不得形成第二个现金池。

## 6. 实现前需要核对的接口口径

- **分配基数：** DEC-COMM-003 是权威决策；DOMAIN_ARCHITECTURE §10.6 已在本 PR 同步为同一完整口径：先汇总非 BD 渠道毛收入，扣除适用且已约定的前置商业成本，得到净商业池，再按投资比例 Pro-rata 分配。
- **渠道开放：** 委员会对应成员开放时手续费为 0%；无成员时，需满足合作历史或声望门槛才可外部代理软绑定；否则渠道关闭、收入为 0。代理费率与声望门槛仍属待标定参数。
- **电视曝光：** 电视倍率只作用于国内配信、玩具/周边、音乐和 BD/DVD；不作用于海外发行与电视版权收入。本 fixture 未启用电视曝光，避免把倍率与分账问题混在同一验算中。
- **Finance 类别：** 实际流水类别必须复用当前 Finance 已批准枚举。本文不新造 category 名称；若现有枚举无法表达上述事实，应先提交契约差异，不得在模块内私自新增。
- **舍入：** 投资本金沿用已冻结的 `floor(total_investment × percent / 100)`；净商业池分配的取整顺序和余数归属尚未冻结。本 fixture 只使用整除输入，不裁定该规则；运行时出现非整除金额前必须先收敛契约，不能在各模块分别舍入。

## 7. 最小验收用例

不扩展为大规模排列组合，仅保留：

1. 样例 A：30% 投资，前置成本先扣，净池按比例分配。
2. 样例 B：100% 投资，玩家获得全部净池，不发生本金优先返还。
3. 样例 C：承制项目只有制作费/制作成本与 BD 公司所得，不产生委员会投资和非 BD 分配。
4. 三个样例均核对 Finance 现金流水只记一次、项目归因和 Archive 记录能还原上述结果；样例 A 按 §2.4 核对期初余额、entry 合计、期末余额与 `finance_summary.profit`。

以上是手算 fixture；金额只为验证口径，不是经济平衡建议。
