# 经济模拟器使用说明

这是独立于游戏运行时的 Python 蒙特卡洛模型，用于复用现金流口径、比较承制/委员会路线，并测试动态工作量、阶段合格线、延期压力与违约扣罚。它不是游戏内核，也不代表所有 V1 机制已经实现。

## 运行

Python 3.10+，无第三方依赖。在仓库根目录执行：

```bash
python scripts/economic_simulator.py
python scripts/economic_simulator.py --config scripts/simulation_config.example.json --out build/economic-sim
python scripts/run_sensitivity.py
python -m unittest discover -s scripts/tests -v
```

默认每种策略运行 500 次；相同代码、配置和 seed 可复现相同结果。输出 `summary.json` 和逐次结果 `trials.csv`。敏感性脚本测试周产能、低完成度交付线和违约处罚。

## 当前制作模型

- 每个项目类型使用数值提案中的标准工作量与标准周期；每个项目实际工作量围绕基础工作量随机浮动。
- 五阶段按脚本 10%、分镜 15%、原画 35%、动画检查 25%、后期 15%分配工作量。
- 每阶段合格线独立动态抽样，位于该阶段工作量的 65%–80%；达到合格线即可进入下一阶段。
- 每阶段有 35%概率选择额外打磨，额外工作量暂按该阶段基础工作量的 20%计算。是否打磨会影响项目实际所需工作量和最终质量。
- 周产能暂按 110 工作量单位建模，并加入 12%随机波动；项目总工作量另有 12%波动。该产能是用于试跑的占位值，不代表员工模块最终产能。
- 合同标准周期为死线。委员会项目在原周期结束时仍未完成全部阶段，可自动使用一次原周期 20%的延期；承制项目不延期。延期期间照常扣每周固定运营费，压力按延期周数增长并在结算时影响声望。
- 截止时未完成全部阶段，但累计完成工作量达到总工作量 50%，按低完成度交付处理；低于该线则违约。50%只是实验阈值，需后续讨论和敏感性测试。

## 现金流口径

- 初始现金 5000 万日元，经营周期 520 周，每周固定运营成本暂按 68 万日元。
- 委员会投资额 = 合同预算 × 2 × 玩家投资比例；资格检查使用拨款前现金。接约时先扣投资，再将合同预算并入公司统一现金池；其他投资方资金不进入公司现金。
- 制作工作量当前不直接转化为制作费用；`production_cost_per_work_unit` 默认 0。员工工资、临时人员、外包和加班尚未接入，因此工作量模型目前只影响进度和项目交付结果。
- 正常或低完成度交付才结算 BD 收入；违约不结算商业收入，另按合同预算比例扣罚。委员会投资本金已在开工时支付，不重复扣除。
- 承制成功奖励、BD分成、商业评分等沿用当前暂定参数；非BD渠道收入默认关闭。

## 重要限制

1. 周产能是全项目统一占位值，尚未接入员工岗位、能力、疲劳、核心/临时员工、外包和加班的实际产能与成本。
2. 项目规模梯度尚未接入；目前每种类型只有标准档，工作量围绕标准值随机变化。
3. 阶段合格线区间、打磨概率/额外工作量、周产能、低完成度交付线、违约扣罚、压力与声望惩罚均为实验变量，不是正式规则。
4. 完成度对质量的影响目前只通过打磨质量增益与随机质量波动表示，尚未建立完整的质量计算公式。
5. 商业评分、渠道收入、员工成长疲劳、事件、招聘、声望对市场机会的反馈等尚未完整接入。

结果适合检查模型流程与参数方向，不足以单独证明经济系统平衡。后续接入员工模块后，必须用真实产能和成本替换占位参数，再重新运行。
